# Клиент VLESS + REALITY в Windows

Проверено по документации 31.10.2026. Основной вариант — **v2rayN 7.25.6 с ядром Xray** на Windows 10/11. Для новых установок предпочтительна поддерживаемая версия Windows. Сервер сначала подготавливают по [инструкции Debian](server-debian.md), либо получают реквизиты у его администратора.

## 1. Что должно быть под рукой

Лучше всего — готовая ссылка `vless://…`. Для ручного ввода нужны:

| Поле | Пример/ожидаемое значение |
|---|---|
| Адрес | Публичный IPv4 VPS |
| Порт | `443` |
| UUID | Выданный сервером идентификатор |
| Encryption | `none` |
| Flow | `xtls-rprx-vision` |
| Transport / Network | `tcp` или `raw` |
| Security | `reality` |
| SNI / ServerName | Проверенное имя сайта прикрытия |
| Fingerprint / uTLS | `chrome` |
| Public key / Password | Значение `Password (PublicKey)` с сервера |
| Short ID | Значение из серверного `shortIds` |
| SpiderX | `/`, если поле есть |

Приватный ключ сервера клиенту не нужен. `Public key` в интерфейсе и `pbk` в ссылке — это тот же клиентский ключ, который в современном JSON называется `password`. [Формат ссылки](https://github.com/XTLS/Xray-core/discussions/716).

## 2. Установка v2rayN

1. Откройте [официальные релизы 2dust/v2rayN](https://github.com/2dust/v2rayN/releases/latest). На дату проверки Latest — `7.25.6`.
2. В `Assets` скачайте `v2rayN-windows-64.zip` для обычного компьютера Intel/AMD. Для Windows ARM64 используйте `v2rayN-windows-arm64.zip`. Архитектуру можно посмотреть: **Параметры → Система → О системе → Тип системы**.
3. Распакуйте **весь архив**, например в `%LOCALAPPDATA%\Programs\v2rayN`. Запуск прямо из ZIP не подходит. В portable-сборке настройки сохраняются рядом с программой, поэтому каталог должен быть доступен для записи вашему пользователю.
4. Запустите `v2rayN.exe`. Обычному прокси-режиму права администратора не нужны. Если Windows блокирует скачанный файл, сначала проверьте источник и сведения о файле; не отключайте защиту целиком.
5. Выберите удобный язык в настройках, если требуется. Названия пунктов ниже даны по смыслу; локализация WPF/Avalonia может отличаться.
6. Проверьте, что доступно ядро **Xray**. Релизные пакеты содержат часть ядер; для обновления используйте меню обновлений приложения и отдельный пункт Xray. После обновления перезапустите ядро и посмотрите версию в журнале. Здесь примеры рассчитаны на `26.10.31`.

Официальная [таблица релизных файлов](https://github.com/2dust/v2rayN/wiki/Release-files-introduction) различает обычную WPF-сборку и `-desktop` на Avalonia. Для этой инструкции достаточно обычной `windows-64.zip`. Если выбранная сборка запрашивает .NET, используйте ссылку на официальный Microsoft Desktop Runtime, которую она показывает, либо соответствующую автономную сборку из официального релиза.

Если GitHub недоступен, скачайте официальный архив через другую доступную сеть и перенесите его на ПК. Не подменяйте приложение случайной сборкой из рекламы. Для обновления со старого клиента учитывайте, что разработчик отдельно отмечает проблему безопасного обновления в версиях `6.10–7.23.2`; исходный архив актуального релиза лучше скачать вручную. [Примечание разработчика](https://github.com/2dust/v2rayN/wiki/Description-of-some-ui).

## 3. Импорт ссылки

1. Скопируйте полную строку `vless://…`, без кавычек, пробелов и переносов.
2. В главном окне выберите импорт ссылки из буфера обмена — обычно **Servers → Import share links from clipboard** или `Ctrl+V`.
3. Найдите добавленную строку в списке, откройте её на редактирование и сопоставьте поля с таблицей шага 1.
4. Выберите для профиля ядро **Xray**, если есть выбор. Для стартовой проверки оставьте Mux выключенным.
5. Сделайте профиль активным через **Set as active server** в контекстном меню. В разных интерфейсах также доступен Enter.
6. Перезапустите службу/ядро через приложение, если оно не перезапустилось само. В информационной панели не должно быть ошибок конфигурации.

Если ссылка не импортируется, добавьте профиль вручную: **Servers → Add VLESS** и заполните таблицу выше. Не выбирайте VMess, Trojan, TLS вместо REALITY, WebSocket или XHTTP для сервера из данного руководства.

Адресом подключения остаётся **IP VPS**. SNI сайта прикрытия заполняется в отдельном поле. Поля Host, path, service name, ALPN оставьте без пользовательских значений, если этого не требует ваш сервер.

## 4. Первая проверка через локальный SOCKS

Пока отключите TUN и другие VPN-клиенты. В настройках v2rayN найдите локальный порт SOCKS/смешанного прокси. Обычно это `10808`, но проверяйте фактическое значение. Здесь и далее замените число, если у вас другой порт. Разрешение подключений из LAN для личного ПК оставьте выключенным.

Откройте PowerShell:

```powershell
Test-NetConnection SERVER_IP -Port 443
curl.exe --max-time 20 --proxy socks5h://127.0.0.1:10808 https://api.ipify.org
curl.exe --max-time 30 --proxy socks5h://127.0.0.1:10808 -I https://example.com
```

`SERVER_IP` замените IP VPS. Здесь важно `curl.exe`: в Windows PowerShell команда `curl` без расширения может означать другую программу. `socks5h` передаёт доменное имя через прокси и не требует локального разрешения имени целевого сайта.

Первый запрос через прокси должен показать IP выхода VPS, второй — HTTP-заголовки сайта. IP для сравнения можно получить на сервере командой `curl -4 https://api.ipify.org`. При ошибке переходите к [диагностике](troubleshooting.md).

## 5. Режим для браузера: системный прокси

После успешного SOCKS-теста:

1. В v2rayN выберите **System proxy → Set system proxy / Automatically configure system proxy**.
2. Для начальной проверки выберите маршрутизацию **Global / Proxy all**. Это означает «всё, что попало в ядро, отправлять в прокси»; приложения, игнорирующие системный прокси, так не перехватываются.
3. Откройте браузер заново, проверьте внешний IP и нужные сайты.
4. Firefox при необходимости настройте на использование системных прокси. Для ручной настройки Firefox можно задать SOCKS v5 `127.0.0.1:10808` и включить **Proxy DNS when using SOCKS v5**.

Системный прокси охватывает браузеры и другие приложения, которые его учитывают. Это отдельный механизм от правил маршрутизации ядра. [Объяснение разработчика](https://github.com/2dust/v2rayN/wiki/Description-of-system-proxy-routing).

Не выбирайте готовое правило «обход Китая» как способ настройки для России: стандартные географические списки проекта ориентированы на другой регион. Сначала добейтесь стабильного Global, затем добавляйте осмысленные исключения для LAN и нужных вам прямых сервисов.

## 6. Режим для остальных приложений: TUN

TUN создаёт виртуальный интерфейс и перенаправляет IP-трафик согласно правилам клиента. Он нужен для программ без SOCKS/HTTP-настроек и части UDP-приложений.

1. Сначала подтвердите работоспособность прокси командами шага 4.
2. Завершите другие VPN/TUN-программы, чтобы не получить конфликт маршрутов.
3. Для этой проверки очистите системный прокси в v2rayN — так проще проверить именно TUN.
4. Полностью выйдите из v2rayN через меню, запустите его **от имени администратора** и подтвердите UAC.
5. Включите **TUN**. Если клиент предлагает выбрать ядро для TUN, сохраните Xray для VLESS-профиля; возможен отдельный TUN-компонент. Дайте приложению установить нужный виртуальный адаптер штатным способом.
6. В настройках TUN включите автоматическую маршрутизацию. В качестве начальных параметров стека и MTU оставьте значения по умолчанию; Xray поддерживает стек `gvisor`. Настройки зависят от выбранного ядра.
7. Убедитесь, что IP VPS исключён из маршрута обратно в туннель: клиент обычно делает это автоматически. Циклический маршрут проявляется тайм-аутом сразу после включения TUN.
8. Включите штатную обработку/перехват DNS для TUN и проверьте политику IPv6. Для всего интернет-трафика IPv6 должен также туннелироваться или блокироваться правилами клиента.
9. Проверьте из обычного PowerShell **без параметра `--proxy`**:

```powershell
curl.exe --noproxy "*" --max-time 20 https://api.ipify.org
curl.exe --noproxy "*" --max-time 30 -I https://example.com
```

Здесь `--noproxy "*"` отключает прикладной HTTP/SOCKS-прокси для проверки: сетевой TUN всё равно должен перехватить соединение. Результат должен соответствовать VPS. После этого проверьте конкретное приложение.

Меню TUN, DNS и поведения ICMP описаны в [официальной wiki](https://github.com/2dust/v2rayN/wiki/Description-of-some-ui). Успешный `ping` не используйте как доказательство: некоторые TUN-ядра отвечают на ICMP локально.

TUN сам по себе не гарантирует блокирование прямого трафика при остановке приложения. Если нужна такая политика, используйте поддерживаемый клиентом режим строгой маршрутизации/защиты от утечек и отдельно проверьте отключение туннеля.

## 7. DNS, IPv6, UDP и проверки утечек

Для браузера через SOCKS отправляйте DNS через SOCKS. При TUN используйте штатную DNS-конфигурацию клиента. В v2rayN можно начать с импорта стандартных DNS-настроек для выбранного ядра; настройка `Remote DNS` отдельно не доказывает, что все DNS-запросы идут через VPS.

Если нужен явный DoH-резолвер, пример стандартного endpoint — `https://cloudflare-dns.com/dns-query`; он должен быть доступен через выбранный маршрут. [Документация Cloudflare DoH](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/dns-over-https-client/). Для Xray стратегия разрешения проксируемых назначений `AsIs` обычно оставляет доменное имя серверу; `Remote DNS` в таком режиме может применяться лишь при сопоставлении IP-правил. Это зависит от текущего конфига v2rayN, а не только от URL резолвера.

Проверьте:

- внешний IPv4 и, при наличии, IPv6 в браузере соответствуют ожидаемому выходу;
- DNS-тест в браузере показывает ожидаемые резолверы; принадлежность резолвера стране VPS не обязательна;
- при закрытом клиенте поведение соответствует вашим ожиданиям;
- после сна и смены Wi-Fi TUN восстанавливается.

Публичный тест утечек получает ваш IP; он проверяет браузерный сценарий, а не каждое приложение. Для точной проверки DNS нужно смотреть сетевой трафик на физическом адаптере.

Vision по умолчанию ограничивает UDP к порту 443 (QUIC), поэтому браузер может перейти на HTTPS по TCP. Это ожидаемое поведение. Не отключайте UDP целиком ради браузера: звонки, игры и другие приложения нужно проверять отдельно. [Режимы flow Xray](https://xtls.github.io/en/config/outbounds/vless.html).

## 8. Автозапуск, обновление, отключение

После проверки включите запуск v2rayN при входе в Windows и, если нужно, автоматическое подключение активного профиля. TUN при старте требует соответствующих прав; проверьте его после реального выхода и входа в систему. Не считайте автозапуск подтверждённым только по установленному флажку.

Перед обновлением сделайте резервную копию через функцию приложения. Обновляйте отдельно интерфейс и ядро, затем повторяйте SOCKS-тест и TUN-тест. Импортированную VLESS-ссылку также храните в защищённом месте.

Для отключения сначала выключите TUN, затем выполните **Clear system proxy**, после этого выйдите из приложения. Если после аварийного закрытия пропал интернет, откройте **Параметры Windows → Сеть и Интернет → Прокси** и отключите оставшийся ручной прокси/сценарий v2rayN, если он больше не нужен. Корпоративные настройки не удаляйте.
